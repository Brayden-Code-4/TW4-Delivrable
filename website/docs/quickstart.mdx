# Get a task into TW4 in 10–15 minutes

This tutorial walks from an empty folder to a task you can list, filter, update and delete. Follow the steps in order. Do not skip the checks.

## What you will do

When you finish, you will be able to:

- run TW4 on your computer
- call `/health`
- create one task with an API key
- filter the list, then PATCH, PUT and DELETE that task

Time: about 10 to 15 minutes.

## What you need

Exact versions that work with this guide:

| Tool | Version |
| --- | --- |
| Git | 2.40 or newer |
| Node.js | **20.0 or newer** (21 and 24 are fine) |
| npm | 10 or newer (it comes with Node) |

Check:

```bash
git --version
node -v
npm -v
```

Node must print `v20` or higher.

You also need a second terminal window. TW4 keeps running in the first one while you send requests in the second.

:::note
This path uses Node, not Docker. For Docker, see [Installation](/docs/installation).
:::

## 1. Clone the repo

```bash
git clone https://github.com/Brayden-Code-4/TW4-Delivrable.git
cd TW4
```

You should see `README.md`, `package.json`, `src` and `website`.

## 2. Copy the env file

```bash
cp .env.example .env
```

PowerShell:

```powershell
Copy-Item .env.example .env
```

Open `.env`. Leave `PORT=3000`. You can keep `API_KEY=change-me-now` for this tutorial, or replace the example key with yours.

## 3. Start the API

```bash
npm install
npm start
```

Wait until you see:

```text
TW4 API listening on http://0.0.0.0:3000
```

Do not close this terminal.

## 4. Ping health

In the **other** terminal:

```bash
curl http://127.0.0.1:3000/health
```

You should get something like:

```json
{"status":"ok","service":"tw4","environment":"development","uptime_seconds":2}
```

If curl fails with "connection refused", the server is not up yet. Go back to step 3.

## 5. Create a task

Git Bash / macOS / Linux:

```bash
curl -s -X POST http://127.0.0.1:3000/api/v1/tasks \
  -H "Content-Type: application/json" \
  -H "X-API-Key: change-me-now" \
  --data-binary '{"title":"Write the user guide","status":"todo"}'
```

PowerShell (do not paste the bash JSON line, PowerShell eats the braces):

```powershell
$body = @{ title = "Write the user guide"; status = "todo" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:3000/api/v1/tasks -ContentType "application/json" -Headers @{ "X-API-Key" = "change-me-now" } -Body $body
```

A good answer has an `id` and `"status":"todo"`. Copy the `id`.

`401` means the key in the header does not match `.env`.

## 6. List tasks

```bash
curl http://127.0.0.1:3000/api/v1/tasks
```

You should see `"count": 1` (or more) and your title in `data`.

List is **not** authenticated. Anyone who can reach port 3000 can see the backlog. That is a local-demo choice, not a bug.

## 7. Filter by status

```bash
curl "http://127.0.0.1:3000/api/v1/tasks?status=todo"
```

`?status=wip` returns `400`. Allowed values: `todo`, `doing`, `done`.

## 8. Update with PATCH, then PUT

Replace `<TASK_ID>` with the UUID from step 5.

```bash
curl -X PATCH http://127.0.0.1:3000/api/v1/tasks/<TASK_ID> \
  -H "Content-Type: application/json" \
  -H "X-API-Key: change-me-now" \
  --data-binary '{"status":"doing"}'
```

`PUT` uses the same handler:

```bash
curl -X PUT http://127.0.0.1:3000/api/v1/tasks/<TASK_ID> \
  -H "Content-Type: application/json" \
  -H "X-API-Key: change-me-now" \
  --data-binary '{"status":"done"}'
```

## 9. Delete the task

```bash
curl -X DELETE http://127.0.0.1:3000/api/v1/tasks/<TASK_ID> \
  -H "X-API-Key: change-me-now"
```

You should see `"deleted": true`. A second GET of that id returns `404`.
