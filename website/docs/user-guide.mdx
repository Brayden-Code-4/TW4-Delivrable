# Use OPNsense day to day

How-to page. The firewall is already installed ([Installation](/docs/installation)). Endpoint tables live in the [API reference](/docs/api/overview). Do not demo both in a row.

Base GUI: `https://192.168.1.1/` (or the LAN IP you set).

## Login and wizard

`root` plus the password from the installer. The first-boot wizard can set hostname, timezone and LAN. You can skip most screens and fix them later under **System → Settings**.

Change the default password if you still have `opnsense`.

## Interfaces

**Interfaces → Assignments** (or console menu **1**): first NIC is usually LAN, second WAN. WAN expects DHCP from the hypervisor NAT or your upstream. LAN is static `192.168.1.1/24` unless you changed it.

Do not turn on hardware offloading in a VM (**Interfaces → Settings**) — the official virtual page asks you to disable it.

## Firmware

**System → Firmware → Updates**. Same data as `GET` / `POST` `/api/core/firmware/status` (see [Firmware status](/docs/api/firmware-status)).

## API keys (for scripts)

**System → Access → Users** → pick a user → API **+**. One key per application. The secret file is a one-time download.

The user must have privileges for the GUI page that owns the endpoint. “Effective Privileges” on the user shows what the key can call.

## When to use the GUI vs curl

| Job | Where |
| --- | --- |
| First install, password, LAN IP | GUI or console |
| Look at services, firmware | GUI, or [API](/docs/api/overview) |
| Automate from a laptop | API + Basic auth |

## Errors you will actually hit

| What | When |
| --- | --- |
| Browser certificate warning | Factory cert. Lab: proceed. Production: install a real cert. |
| Cannot reach `.1` | You are not on the LAN network. |
| API HTML login page | Not authenticated, or wrong privileges. |
| Lost API secret | Create a new key. OPNsense will not show the old one. |
